# Isro PR: Project Specification

> A lightweight web platform that makes every Indian citizen space-aware.
> Admins publish stories about ISRO, space missions, and Indian space startups. Each story is narrated in multiple Indian languages with Gnani Timbre v2.5. Anyone can listen by language and category, or ask questions in text or voice in a WhatsApp-style chat.

---

## 1. Summary

| Area | Who uses it | What it does |
|---|---|---|
| **Library** | Public visitors (no login) | Browse stories, filter by language and category, play audio like a podcast, read transcripts |
| **Chat** | Public visitors (no login) | Ask questions by text or voice. Text gets a text reply. Voice gets a voice-note reply. Answers are live, generated by an LLM from a knowledge base. |
| **Admin panel** | Admin only (login required) | Write and publish stories, generate audio per language with Gnani, manage the knowledge base for chat, view chat activity, manage settings |

### What is included
- Public library, story player, and chat (no login)
- Admin login and admin dashboard
- Story authoring, translation fields, and audio generation through Gnani
- Live chat with text and voice, powered by Gnani Prisma v2.5 (STT), an LLM API, and Gnani Timbre v2.5 (TTS)
- Simple retrieval (RAG) over the admin-managed knowledge base

### What is not included (for now)
- User accounts, sign-up, or saved profiles for public users
- Payments, comments, likes, or social features
- Automatic web scraping or live news ingestion (admins add facts by hand, with sources)
- Native mobile apps (the site is mobile-first and works as a PWA later)
- Embedding-based vector search (keyword search with SQLite FTS5 is used first, upgradeable later)

### Design principles
1. **Light:** few dependencies, one server process, one database file, one audio folder.
2. **Easy to manage:** everything an admin does happens in the browser. No terminal needed for normal work.
3. **Cheap to run:** audio is generated once and reused. Chat audio is cached.
4. **Safe by default:** API keys only on the server. Public endpoints are rate-limited. Admin routes require login.
5. **Honest answers:** the chat answers only from the knowledge base and says so when it doesn't know. Every answer shows its source and "as of" date.

## 2. Tech Stack

| Layer | Choice | Why |
|---|---|---|
| Runtime | Node.js 20+ | One language across server and scripts |
| Server | Express | Small, well known, easy to host |
| Database | SQLite via `better-sqlite3` | One file, no database server, FTS5 for search |
| Auth (admin only) | Single admin account, password hashed with `bcrypt`, session in an httpOnly cookie signed with `jsonwebtoken` | No user system needed |
| Uploads | `multer` (audio uploads from chat, cover images) | Standard |
| Audio conversion | `ffmpeg` (system binary, optional but recommended) | Converts browser audio to a format Prisma accepts. Joins TTS chunks. |
| Frontend | Plain HTML, CSS, vanilla JavaScript (ES modules), served by Express | No build step, tiny bundle |
| Styling | One hand-written CSS file with CSS variables | No UI framework needed |
| LLM | One provider behind a small adapter (choose one at setup) | Swap providers without changing app code |
| Audio cache | Local folder `data/audio/` | Simple. Can move to object storage later. |
| Hosting | Any small Node host with a persistent disk (VPS, Render, Railway, Fly.io) | SQLite and audio need a disk that survives restarts |

Do not add React, Next.js, Redis, Postgres, or a separate worker service in v2. If load grows, revisit the stack then.

**Hosting note:** v1 was pure static hosting. The live chat and admin panel need a server to keep API keys secret, so this version needs one small Node host with persistent storage. It is still a single deployable app.

## 5. Data Model (SQLite)

### 5.1 Tables

**admins**
- `id`, `email` (unique), `password_hash`, `created_at`

**stories**
- `id` (slug, primary key, e.g. `chandrayaan-3`)
- `title`, `summary`, `category` (`isro` | `startup` | `legacy` | `explainer`)
- `cover_path` (optional), `published` (0/1), `pinned` (0/1)
- `facts_as_of` (date, required for missions and startups)
- `sources` (JSON array of URLs)
- `duration_hint_min` (integer, optional)
- `created_at`, `updated_at`

**story_translations**
- `story_id`, `lang` (primary key together)
- `body` (the script, plain text, spoken style)
- `voice` (Timbre voice name)
- `reviewed` (0/1), `review_note` (optional)
- `audio_status` (`none` | `queued` | `generating` | `ready` | `failed`)
- `audio_path` (nullable), `audio_hash`, `audio_duration_sec`, `audio_error`
- `updated_at`

**knowledge**
- `id`, `title`, `body` (plain text, a few paragraphs max)
- `category`, `source_url`, `as_of` (date), `created_at`, `updated_at`
- FTS5 virtual table `knowledge_fts` over `title` and `body`

**chat_sessions**
- `id` (random token stored in an httpOnly cookie), `created_at`, `last_seen_at`, `lang_pref`

**chat_messages**
- `id`, `session_id`, `role` (`user` | `assistant`)
- `input_type` (`text` | `voice`)
- `lang` (detected or chosen), `text` (user text or transcript, assistant text)
- `audio_path` (nullable, for voice replies), `audio_hash`
- `sources` (JSON, for assistant answers), `status` (`ok` | `error` | `refused`)
- `created_at`

**jobs**
- `id`, `type` (`tts_story` | `tts_chat`), `payload` (JSON), `status` (`queued` | `running` | `done` | `failed`), `attempts`, `error`, `created_at`, `finished_at`

**settings**
- `key` (primary key), `value` (JSON)
- Keys: `llm_provider`, `llm_model`, `enabled_languages`, `chat_max_audio_sec`, `chat_retention_days`, `rate_limits`

### 5.2 Retention
- Chat sessions and messages older than `chat_retention_days` (default 30) are deleted by a daily cleanup job.
- Temporary uploads in `data/uploads/` are deleted right after transcription, or after 10 minutes if something fails.

## 6. Public Features (No Login)

### 6.1 Library (`/`)

- **Header:** logo, language selector, links to Library, Chat, About.
- **Language selector:** shows enabled languages by their native names (हिन्दी, தமிழ், తెలుగు, বাংলা, English). Default: browser language if enabled, otherwise English. Saved in `localStorage`.
- **Category filter:** All, ISRO Missions, ISRO Legacy, Startups, Explainers.
- **Search:** searches titles and summaries in the selected language.
- **Story cards:**
  - Cover, title, summary, approximate duration, category tag
  - "Listen" button if audio exists in the selected language
  - "Read" badge if no audio exists in that language (opens the text)
  - "Facts as of [date]" label on missions and startups
- **Empty state:** a clear message when a filter returns no results.
- **Pinned stories** appear first in the chosen category.

### 6.2 Story Player (`/story.html?id=<slug>`)

- Title, category, summary, "Facts as of" date, and source links.
- **Audio player:**
  - Play and pause
  - Skip back and forward 15 seconds
  - Seekable progress bar with current and total time
  - Speed: 0.75x, 1x, 1.25x, 1.5x (remembered in `localStorage`)
  - Sticky mini player when scrolling
  - Lock-screen controls through the Media Session API
- **Language switcher:** changes the audio and transcript to another language on the same story. Keeps position if durations are similar, otherwise restarts.
- **Transcript:** toggle, shown as paragraphs in the selected language.
- **Up next:** three other stories in the same category.
- Audio uses `preload="none"`. No autoplay.

### 6.3 Chat (`/chat.html`)

WhatsApp-style interface. No login. Each browser gets an anonymous session cookie.

**Layout**
- Top bar: "Space Buddy" name and avatar, a small status line ("online" or "typing…").
- Message list: user messages on the right, bot messages on the left, grouped by time.
- Composer at the bottom: text box, send button, and a hold-to-record mic button.
- Language selector in the top bar (defaults to the library language). Used for voice replies when the speech language cannot be detected.

**Text message flow**
1. User types and sends.
2. Server checks rate limit and message length (max 500 characters).
3. Server retrieves relevant knowledge base entries (see section 8).
4. LLM writes a short reply in the user's language. Reply is text.
5. Bot bubble appears with the text, the source line ("Source: ISRO, as of Oct 2026"), and a small "Listen" button that generates voice on demand (optional, see 6.3.3).

**Voice message flow**
1. User holds the mic button. Recording shows a timer and a waveform. Max length from settings (default 30 seconds). Releasing the button sends the note. Sliding away cancels it.
2. The browser sends the audio file to `POST /api/chat/voice`.
3. Server converts the audio to WAV, 16 kHz, mono with ffmpeg.
4. Server sends the audio to Gnani Prisma v2.5 STT. Gets the transcript and detected language.
5. Server runs the same retrieval and LLM flow as text, asking for a reply in the detected language.
6. Server sends the reply text to Gnani Timbre v2.5 TTS with the matching `language` code and voice. Saves the MP3 in `data/audio/chat/<hash>.mp3`.
7. Response contains the transcript, the reply text, and the audio URL.
8. UI shows the user's voice note bubble with the transcript under it, then a bot voice-note bubble (play button, duration, waveform) with the reply text under it.

**Voice reply rules**
- Voice in gets voice out. Text in gets text out. The bot does not send a voice note to a text message.
- Optional setting: "Always send voice replies" (off by default).
- Voice replies are short: about 20 to 30 seconds of speech, or roughly 60 to 80 words. The LLM is told to keep answers in that range.
- Text is always shown alongside the voice note, so users can read it.

**Chat safety rules**
- If no knowledge base entry is relevant, the bot says it does not have that information yet and suggests checking ISRO's official site. It does not guess.
- Date questions (launch dates, timelines) must use knowledge base dates and show "as of." The bot never invents a date.
- Off-topic questions get a short, friendly redirect to space and Indian space topics.
- Refuses requests for personal data, medical or legal advice, and anything harmful. Responds briefly and politely.
- Never claims to be a human. It is "Space Buddy, an AI assistant."

**Chat UI behavior**
- Show a typing indicator while the server works.
- If STT fails or returns nothing, show "I couldn't hear that. Try again or type your question."
- If TTS fails, show the text reply and a small note "Voice reply unavailable right now."
- Keep a local copy of the visible messages in `sessionStorage` only, so refresh does not lose them. Server history is kept for admin review and retention only.

**Mobile specifics**
- Request microphone permission on first mic tap, not on page load.
- Use `MediaRecorder`. Prefer `audio/webm` or `audio/mp4` depending on browser support. The server handles conversion.
- Works on Chrome for Android and Safari on iOS. Test both.

## 7. Admin Panel (Login Required)

### 7.1 Login
- Route: `/admin/login.html`
- Email and password. No sign-up page.
- Admin accounts are created only with the CLI: `npm run admin:create -- --email you@example.com`
- Passwords hashed with bcrypt (cost 12).
- Session cookie: httpOnly, secure in production, sameSite=strict, 8-hour expiry.
- Login attempts rate-limited to 5 per 15 minutes per IP.
- Logout clears the cookie.

### 7.2 Dashboard
- Counts: stories (published / draft), audio ready / queued / failed, knowledge entries, chats in last 7 days.
- Table of recent audio jobs with status and retry button.
- Warning banner if `GNANI_API_KEY` or the LLM key is missing or invalid (checked on demand).

### 7.3 Story Editor (`/admin/story-edit.html?id=<slug>`)

**Story fields**
- Title, slug (auto from title, editable before first save), category, summary
- Cover image upload (JPG or PNG, max 2 MB, resized on upload)
- Facts as of (date), sources (one URL per line, validated), pinned, published
- Duration hint (minutes)

**Translations**
- One tab per enabled language. English is the source.
- Body text area with word count and estimated listening time (about 150 words per minute).
- Voice dropdown (defaults from settings, can override).
- "Mark reviewed" checkbox with optional review note.
- Character counter with the Timbre per-request limit shown (value confirmed during setup, see section 15).

**Audio actions**
- "Generate audio" per language. Adds a job to the queue. Status shows queued, generating, ready, or failed.
- "Generate all languages" button for the story.
- "Regenerate" only when the text, voice, or model changed (hash mismatch). Otherwise the button reads "Up to date."
- Play preview of the generated audio in the admin page.
- Failed jobs show the error and a retry button.

**Publishing rules**
- A story can be published only if English body is filled in and English audio is ready.
- Other languages can be missing audio. Those show as "Read" in the library.
- Publishing a story with a missing or unreviewed translation shows a warning, but does not block publish.

**Saving**
- Saves are automatic as drafts every 30 seconds, plus an explicit Save button.
- Deleting a story asks for confirmation and removes its audio files.

### 7.4 Audio Generation Jobs

Audio generation runs in the server process. It does not block the admin UI.

- Jobs are rows in the `jobs` table. A worker loop picks one queued job at a time (concurrency 1 by default, configurable).
- For each job:
  1. Load the translation body and voice.
  2. Compute hash of (body + voice + model + lang).
  3. If the file exists and the hash matches, mark done.
  4. Split the body into chunks at sentence boundaries under the Timbre per-request limit.
  5. Call Gnani TTS per chunk, with retries (3 attempts, backoff 1s, 2s, 4s).
  6. Join chunks into one MP3 with ffmpeg.
  7. Write to `data/audio/stories/<slug>/<lang>.mp3`, update `audio_status`, `audio_hash`, `audio_duration_sec`.
  8. On failure, set `audio_status = failed` and store the error.
- Jobs survive a restart. On boot, jobs stuck in `running` are reset to `queued`.

### 7.5 Knowledge Base (`/admin/knowledge.html`)

The knowledge base is what the chat uses to answer. Admins add facts by hand, with sources.

- Create, edit, delete entries.
- Fields: title, body (short, factual, plain text), category, source URL, "as of" date.
- Required: source URL and as-of date. The chat cannot cite entries without them.
- Search box over entries (uses the same FTS5 index).
- "Preview" button shows what the chat would retrieve for a sample question.
- Bulk import from CSV (optional, phase 2 of this spec).

Guidance shown on the page: "Write one fact per entry. Keep it short. Add the official source. Update the 'as of' date whenever you check it again."

### 7.6 Chat Activity (`/admin/chats.html`)

- Read-only list of recent sessions (anonymous IDs only) with message counts and time.
- Open a session to see messages, input type, language, and sources used.
- Flag button marks an answer for review (stored in the database, no public effect).
- Delete a session manually.
- No export in v2. Retention rule applies.

### 7.7 Settings (`/admin/settings.html`)

- Enabled languages (for listening and chat input, two toggles per language).
- Default voice per language.
- LLM provider and model (dropdown from the adapter list).
- Chat limits: max message length, max voice note seconds, rate limit per IP per minute.
- "Always send voice replies" default toggle.
- Retention days for chat logs.
- Test buttons: "Test Gnani STT", "Test Gnani TTS", "Test LLM". Each makes one small call and shows success or the error message.

API keys are not editable from the browser. They come from environment variables on the server.

## 8. Chat Backend (RAG + LLM)

### 8.1 Retrieval
- Use SQLite FTS5 over `knowledge` (title and body).
- Query: the user's message (typed or transcribed). Keep the top 3 to 5 entries by BM25 rank.
- Also include the stories table (title and summary) as a secondary source, for questions about a story.
- If nothing matches, the LLM receives "no relevant entries found" and must answer with the "I don't have that yet" behavior.
- Retrieval works for Hindi, Tamil, Telugu, and Bengali by using the same entries in English. Admins write knowledge entries in English. The LLM translates into the user's language. (Later: store translated entries.)

### 8.2 Prompt Contract

System prompt (stored in `server/services/chat.js`, not hardcoded in the browser):

- You are "Space Buddy", a friendly assistant about Indian space missions, ISRO, and Indian space startups.
- Answer only from the provided context. If the context does not contain the answer, say you don't have that information yet and suggest checking isro.gov.in.
- Reply in the language given. Use simple, friendly, conversational tone, like talking to a friend.
- Keep voice answers under 70 words. Text answers under 120 words.
- When giving dates or specs, include "as of" from the context.
- Do not invent launch dates, specifications, or numbers.
- Never claim to be a human.

Input to the LLM:
- System prompt
- Language code and name
- Retrieved entries (title, body, source URL, as-of date) in a clearly labeled block
- Recent conversation turns (last 4 messages from this session)
- The user's current message
- Mode: `text` or `voice` (voice mode asks for shorter output)

Output: plain text, no markdown, no bullet points, no emojis (since it will be spoken).

### 8.3 Provider Adapter

`server/services/llm/` contains one file per provider with the same function:

```
generateReply({ system, messages, maxTokens }) -> { text, usage }
```

- Start with one provider. Add others only when needed.
- Timeout: 15 seconds. On timeout, reply with "I'm taking too long. Please try again."
- Keys come from environment variables only.

### 8.4 Speech Services

**Prisma v2.5 (STT)** — `server/services/gnani/stt.js`
- Input: converted WAV, 16 kHz, mono.
- Output: transcript, detected language, confidence if provided.
- Timeout: 10 seconds.
- Reject audio shorter than 0.5 seconds or with empty transcript.

**Timbre v2.5 (TTS)** — `server/services/gnani/tts.js`
- Input: reply text, language code, voice name.
- Output: audio saved as MP3 in `data/audio/chat/<hash>.mp3`.
- Cache key: hash of (text + voice + language + model). Same answer is not generated twice.
- Timeout: 15 seconds.

### 8.5 Language Handling
- If STT returns a language that is enabled for chat input, use it.
- If STT returns an unsupported or unknown language, use the chat's selected language and tell the user briefly: "I heard you in a language I can't reply to yet. Here's my answer in Hindi."
- Hinglish input: use the `hi-en` path if Prisma detects code-mixed speech and `hi-en` is enabled. Otherwise reply in Hindi.

### 8.6 Latency Budget (target)
- Text reply: under 4 seconds.
- Voice reply: under 8 seconds from release to voice note ready. Show the transcript and text answer as soon as they are ready, then the audio bubble.

## 10. Security and Privacy

- **Secrets:** `GNANI_API_KEY`, LLM key, `JWT_SECRET`, and admin password hash live in environment variables only. Never sent to the browser. Never logged.
- **Rate limits:** public endpoints 60 requests per minute per IP. Chat endpoints 20 messages per minute per session and 5 voice notes per minute per session. Login 5 attempts per 15 minutes per IP.
- **Upload limits:** voice notes max 2 MB and max 30 seconds (checked server-side after conversion). Images max 2 MB. Accept only audio MIME types and image types listed above.
- **Input limits:** chat text max 500 characters. Story body max 20,000 characters. Knowledge body max 3,000 characters.
- **Headers:** Helmet defaults on. Content-Security-Policy allows self, Google Fonts, and no third-party scripts.
- **CORS:** same origin only. No public API from other domains.
- **Personal data:** the chat stores no name, phone, or email. Session IDs are random. Voice recordings are not stored after transcription. Transcripts and text replies are stored for the retention period only.
- **Abuse:** the bot refuses unsafe requests. Admins can delete sessions. Rate limits prevent cost abuse.
- **Admin hardening:** cookies are httpOnly, secure in production, sameSite=strict. Admin actions are logged to a simple `admin_log` table (action, time, target).
- **Dependency hygiene:** `npm audit` before each release. Pin major versions.

## 12. Hosting

- **Requirements:** Node.js 20+, a persistent disk of at least 5 GB (for audio and database), `ffmpeg` installed, HTTPS.
- **Suitable hosts:** a small VPS (e.g. 1 vCPU, 1 GB RAM is enough for launch), Render with a persistent disk, Railway with a volume, or Fly.io with a volume.
- **Process:** one Node process. Use PM2 or the host's process manager to restart on crash.
- **Reverse proxy:** Nginx or the host's built-in proxy for HTTPS.
- **Backups:** daily copy of `data/spacebharat.db` and `data/audio/` to another location. The `backup` script handles it. Test a restore once before launch.
- **Logs:** write to stdout. Keep errors and Gnani/LLM call failures. Do not log user messages or audio.
- **Caching:** `/media/audio/*` with `Cache-Control: public, max-age=31536000, immutable` (files are named by hash). HTML and JSON API responses with short cache.
